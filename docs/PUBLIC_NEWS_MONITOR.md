# 免Key公开消息监控

个人日报在北京时间周二至周六08:30采集关注标的的近期消息，沿用10:15补查和持久化推送去重。支持原有手动分析；本次不增加其他定时推送频率。

## 采集和AI各负责什么

采集器获取有日期和来源链接的公开新闻材料，现有AI解释其可能影响、风险与待验证条件。当前配置模型为DeepSeek，并非在GitHub Actions中调用ChatGPT网页版。ChatGPT订阅不能直接充当Actions的联网搜索API；无需为此另外申请OpenAI或Tavily Key。

不能用模型记忆填新闻、用新闻估计股价/市值、把报道标题当作已证实事件，或凭单条评论判断确定性投资机会。数值行情与指标继续来自原有数据源。

## 数据来源与边界

个人入口 `scripts/personal_investment.py` 按以下顺序查找：现有Yahoo新闻 → 已配置的Tavily/其他搜索服务 → Yahoo Finance公开RSS → 必要时Google News公开RSS。已有Key与渠道保留。未配置的Tavily仍是未配置，不会伪装成已通过API测试。

公开源通过原项目 `IntelligenceService` 抓取和解析，保留DNS/私网限制、响应大小上限、受控重定向与超时；不增加解析依赖，不绕过登录、人机验证、付费墙或网站限制。每个资产最多查询两个公开Feed，已有可用来源就停止；同一次任务缓存成功和失败结果。新任务会重新检查近期消息。

- 只收录近72小时、允许最多5分钟时钟偏差的消息；缺日期、过期、未来时间或不相关消息均丢弃。发布日期不改写为采集时间。
- CRCL匹配Circle公司/股票/USDC业务身份，裸同名代币不作为股票新闻；HOOD匹配Robinhood，COIN匹配Coinbase；BTC/ETH采用Bitcoin/Ethereum身份。
- 优先选择已登记的公司域名和媒体域名。未评级来源被过滤，名单不代表对其报道真实性的保证，也不代表完整覆盖所有新闻。
- 去除常见追踪参数，按原始URL或标准化标题去重。Google News链接明确标为“聚合入口”，不把聚合页冒充已打开的原文。
- RSS只提供标题/摘要/发布时间。报告标注“报道线索”，保存 `evidence_scope`，不声称已核验全文、交叉验证事件或确认事实。AI必须以“据报道/待验证”解释这类材料。
- 股票/API新闻与社区舆情和价格是不同字段，新闻缺失不填为中性；采集失败或过滤后无结果继续显示数据不可用。

源覆盖和网站可用性可能变化，没有商业API的服务保证。公司公告只有在Feed中实际出现且匹配公司来源时才收录，不声称已扫描所有IR/SEC公告。

## 运行与观察

正常01个人工作流已启用此备选机制，不需要手工添加Key。需要关闭时在Repository variables设置 `PUBLIC_NEWS_FALLBACK_ENABLED=false`。它不修改原版Web/Agent/00手动股票入口的新闻语义；新增能力的中文文档仅针对本Fork，原版英文总览未改。

Actions → 每日投资分析（个人微信）→ Run workflow → analysis，可勾选 `no_notify` 只研究归档。同日需要再推送新版测试时明确选择 `resend`。已有认领会在自动任务获取数据之前跳过，避免补查造成API和微信重复。

原始记录在报告证据JSON的各资产 `news`、`news_monitor` 中，含来源、采集时间、原发布时间、核验范围、各源成功/失败及过滤计数。原有AI字段引用 `news:序号`，正文继续区分客观数据和AI推断。完整研究报告归档到 `investment-history`，微信含查看入口。

本机制补的是新闻材料，不补充缺失的加密市值、连续财报变化或加密社区模块；这些字段继续明确不可用，不能用消息替代。

回滚：将上述Variable设为false即可停用公开源，保留已配置API和其他研究功能；或恢复本功能前的代码提交。
